## Què hi ha en aquesta guia

Documentació oficial: `man systemd.network` i la [documentació de networkd](https://www.freedesktop.org/software/systemd/man/latest/systemd.network.html).

systemd-networkd és qui gestiona la xarxa per sota de Netplan, i porta un servidor DHCP integrat. Netplan no el sap configurar, així que aquí **apartem Netplan** i escrivim els fitxers `.network` directament. No cal instal·lar res.

## L'escenari d'exemple

Tota la guia parteix d'aquest cas. **Són dades d'exemple**: a l'activitat tindràs una xarxa, un rang i un DNS diferents, i són els que has de posar als teus fitxers.

Tinc un Ubuntu Server a IsardVDI amb dues targetes:

- `enp1s0`, connectada a **puigcastellar1**, en automàtic (DHCP). Aquí ja reparteix el DHCP del centre: no hi poso el meu.
- `enp2s0`, connectada a **personal1**, amb IP fixa. Aquí ofereixo DHCP als clients.

| Dada | Valor |
| --- | --- |
| IP fixa de `enp2s0` | `192.168.1.1/24` |
| Rang per a 200 equips | `192.168.1.50` – `192.168.1.249` |
| DNS per als clients | `1.1.1.1` (Cloudflare) |
| Porta d'enllaç | cap: encara no hi ha sortida a Internet |

No hi ha d'haver cap altre servidor DHCP actiu a personal1.

## 1. Configuració del servei

<details class="fold">
<summary>Mostra els passos</summary>

Treballa per SSH des de l'amfitrió i **conserva accés a la consola d'Isard**: en apartar Netplan es pot tallar la connexió.

1. **Comprova els noms de les targetes** i el YAML existent. A Isard solen ser `enp1s0` (externa) i `enp2s0` (interna); adapta'ls si són diferents.

   ```bash title="Terminal"
   ip -brief a
   sudo cat /etc/netplan/*.yaml
   ```

2. **Crea el fitxer de la targeta externa** i enganxa-hi el contingut de l'apartat 2:

   ```bash title="Terminal"
   sudo mkdir -p /etc/systemd/network
   sudo nano /etc/systemd/network/10-externa.network
   ```

3. **Crea el fitxer de la targeta interna** i enganxa-hi el contingut de l'apartat 2, amb les dades del teu cas:

   ```bash title="Terminal"
   sudo nano /etc/systemd/network/20-personal.network
   ```

4. **Aparta Netplan i aplica el canvi.** Desa els YAML en una subcarpeta: Netplan deixarà de generar la configuració anterior.

   ```bash title="Terminal"
   sudo mkdir -p /etc/netplan/apartat-ra1
   sudo mv /etc/netplan/*.yaml /etc/netplan/apartat-ra1/
   sudo netplan apply
   sudo networkctl reload
   sudo networkctl reconfigure enp1s0 enp2s0
   ```

   Si es talla SSH, continua des de la consola. `reload` rellegeix els fitxers i `reconfigure` aplica la configuració a les targetes indicades.

Per recuperar Netplan, retira els dos fitxers `.network`, torna els YAML a `/etc/netplan/` i aplica'ls des de la consola.

</details>

## 2. Anàlisi dels fitxers de configuració

<details class="fold">
<summary>Mostra l'anàlisi</summary>

Els fitxers van a `/etc/systemd/network/` i es llegeixen per ordre alfabètic, per això porten un número al davant. Els valors són els de l'escenari d'exemple.

### La targeta externa

```ini title="10-externa.network"
[Match]
Name=enp1s0

[Network]
DHCP=ipv4
```

- `Name`: nom real de la targeta a la qual s'aplica el fitxer.
- `DHCP=ipv4`: continua rebent la IP del centre per DHCP.

### La targeta interna i el servidor DHCP

```ini title="20-personal.network"
[Match]
Name=enp2s0

[Network]
Address=192.168.1.1/24
DHCPServer=yes

[DHCPServer]
PoolOffset=50
PoolSize=200
DNS=1.1.1.1
EmitRouter=no
```

- `Address`: IP fixa i prefix del servidor a `personal1`.
- `DHCPServer=yes`: activa el servidor DHCP en aquesta interfície. Només aquesta targeta n'oferirà.
- `PoolOffset=50`: el rang comença 50 adreces després de l'adreça de xarxa `192.168.1.0`, a `192.168.1.50`.
- `PoolSize=200`: reparteix 200 adreces, de `192.168.1.50` a `192.168.1.249`.
- `DNS`: servidor DNS que s'ofereix als clients.
- `EmitRouter=no`: no anuncia porta d'enllaç; aquest servidor encara no dona sortida a Internet.

</details>

## Comprovar servidor i client

```bash title="Terminal"
networkctl status enp2s0
sudo ss -ulnp
sudo journalctl -u systemd-networkd -n 30 --no-pager
```

Comprova la IP fixa, el fitxer `20-personal.network` i el port UDP 67. El client connectat a `personal1` ha de rebre una IP del rang, el DNS i arribar al servidor.

Per capturar DORA, inicia la captura DHCP abans de connectar un client sense concessió. Una renovació pot mostrar només Request/ACK. Alguns clients negocien _Rapid Commit_ (dos missatges); per observar els quatre, desactiva aquesta opció al client. Al Desktop comprova si el gestor és NetworkManager; `networkctl` correspon a networkd.
