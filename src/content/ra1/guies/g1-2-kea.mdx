## Què hi ha en aquesta guia

Documentació oficial: [kea.readthedocs.io](https://kea.readthedocs.io)

Kea és el servidor DHCP que ha substituït `isc-dhcp-server`, abandonat el 2022. Si busques per Internet trobaràs molta documentació d'`isc-dhcp-server` amb una altra sintaxi: **no et serveix**. Kea es configura amb un fitxer **JSON** i només ens cal el servei d'IPv4, `kea-dhcp4-server`.

## L'escenari d'exemple

Tota la guia parteix d'aquest cas. **Són dades d'exemple**: a cada activitat tindràs una xarxa, un rang i unes reserves diferents, i són les que has de posar al teu fitxer.

Tinc un Ubuntu Server a IsardVDI amb dues targetes:

- `enp1s0`, connectada a **puigcastellar1**, en automàtic (DHCP). Per aquesta xarxa ja reparteix adreces el DHCP del centre; si hi posés el meu, tindria dos servidors responent als mateixos clients.
- `enp2s0`, connectada a **personal1**, amb IP fixa (guia [G1.1](../../guies/g1-1-netplan/)). Aquí munto la meva xarxa: els clients als quals donaré servei.

| Dada | Valor |
| --- | --- |
| Targeta que presta DHCP | `enp2s0` (personal1) |
| Xarxa | `192.168.1.0/24` |
| IP del servidor i porta d'enllaç | `192.168.1.1` |
| DNS per als clients | `1.1.1.1` (Cloudflare) |
| Domini | `aula.internal` |
| Rang per a 200 equips | `192.168.1.50` – `192.168.1.249` |
| Reserves | `.11` i `.12`, fora del rang |

## 1. Instal·lació i configuració del servei

<details class="fold">
<summary>Mostra els passos</summary>

Punt de partida: la targeta `enp2s0` ja ha de tenir IP fixa (guia [G1.1](../../guies/g1-1-netplan/)). Sense això, Kea no arrencarà.

1. **Instal·la el servei d'IPv4**, que és l'únic que necessites:

   ```bash title="Terminal"
   sudo apt update
   sudo apt install -y kea-dhcp4-server
   ```

2. **Aparta el fitxer original.** El que porta el paquet és molt llarg i ple de comentaris; no l'editis. Queda com a còpia per si l'has de consultar:

   ```bash title="Terminal"
   sudo mv /etc/kea/kea-dhcp4.conf /etc/kea/kea-dhcp4.conf.original
   ```

3. **Crea el fitxer nou** i enganxa-hi el fitxer complet de l'apartat 2, amb les dades del teu cas:

   ```bash title="Terminal"
   sudo nano /etc/kea/kea-dhcp4.conf
   ```

4. **Comprova la sintaxi abans d'arrencar.** Kea té un mode de prova que llegeix el fitxer i et diu si està bé:

   ```bash title="Terminal"
   sudo -u _kea kea-dhcp4 -t /etc/kea/kea-dhcp4.conf
   ```

   Va com l'usuari `_kea`, el del servei, i no com a `root`: l'AppArmor que porta el paquet no deixa que el programa obri fitxers fora dels seus. Si t'hi descuides, la resposta és `Unable to open file` encara que el fitxer hi sigui.

   Si falta una coma o una clau, aquí ho sabràs, amb el fitxer, la línia i la columna: `syntax error, unexpected max-valid-lifetime, expecting "," or }`. Si tot va bé, acaba amb codi 0; pot mostrar missatges de registre.

5. **Arrenca i comprova** que està actiu:

   ```bash title="Terminal"
   sudo systemctl restart kea-dhcp4-server
   sudo systemctl status kea-dhcp4-server
   ```

   Ha de sortir `active (running)` en verd.

6. **Verifica que escolta** al port 67:

   ```bash title="Terminal"
   sudo ss -ulnp | grep :67
   ```

7. **Mira les concessions en directe** mentre arrenques el client:

   ```bash title="Terminal"
   sudo journalctl -u kea-dhcp4-server -f
   ```

   Veuràs línies `DHCP4_LEASE_ALLOC` amb la MAC i la IP concedida. La llista completa de concessions la tens a `/var/lib/kea/kea-leases4.csv`.

<Callout kind="nota">

**Ubuntu 26.04** El paquet porta Kea 3.0. Molta documentació i molts tutorials escriuen la validació com `sudo kea-dhcp4 -t`, sense l'usuari: així no funciona, perquè el perfil d'AppArmor del paquet no deixa que el programa obri el fitxer. Compara sempre amb la sortida de la teva màquina.

</Callout>

</details>

## 2. Anàlisi del fitxer de configuració

<details class="fold">
<summary>Mostra l'anàlisi</summary>

El fitxer és `/etc/kea/kea-dhcp4.conf`. Només has de tocar aquests quatre trossos; la resta de camps (temps de concessió, base de dades de concessions, registre) els deixes com estan. Els valors són els de l'escenari d'exemple.

### La interfície

```json title="interfaces-config"
"interfaces-config": {
  "interfaces": [
    "enp2s0"
  ],
  "dhcp-socket-type": "raw"
},
```

- `interfaces`: la **targeta que presta DHCP**, `enp2s0`, connectada a personal1. Mai la que va a la xarxa del centre.
- Revisa el nom real amb `ip -brief a`; pot canviar segons la VM.

### La xarxa i el rang

```json title="subnet4"
"subnet4": [
  {
    "id": 1,
    "subnet": "192.168.1.0/24",
    ...
    "pools": [
      {
        "pool": "192.168.1.50 - 192.168.1.249"
      }
    ],
```

- `subnet` és l'**adreça de xarxa amb prefix**, `192.168.1.0/24`. No és la IP del servidor (`192.168.1.1`).
- `pool` és el rang que es reparteix sense reserva: de `.50` a `.249`, ambdós inclosos, 200 adreces per als 200 equips. Exclou servidor, IP manuals i reserves.

### Les opcions per als clients

```json title="option-data"
"option-data": [
  {
    "name": "routers",
    "data": "192.168.1.1"
  },
  {
    "name": "domain-name-servers",
    "data": "1.1.1.1"
  },
  {
    "name": "domain-name",
    "data": "aula.internal"
  }
],
```

- `routers`: porta d'enllaç que rebran els clients, el mateix servidor, `192.168.1.1`. Per sortir a Internet, aquest servidor també necessita encaminament i NAT: [G1.3](../../guies/g1-3-nftables/).
- `domain-name-servers`: DNS que rebran els clients, `1.1.1.1`.
- `domain-name`: nom de domini comunicat al client, `aula.internal`. Aquesta opció no crea un servidor DNS.

### Les reserves

```json title="reservations"
"reservations": [
  {
    "hw-address": "08:00:27:5c:eb:99",
    "ip-address": "192.168.1.11"
  },
  {
    "hw-address": "08:00:27:2d:8d:a2",
    "ip-address": "192.168.1.12"
  }
]
```

- `hw-address` és la MAC real del client i `ip-address`, la IP reservada que rebrà. El client continua configurat per DHCP.
- Les reserves `.11` i `.12` queden fora del rang. Les MAC són exemples.
- Si només necessites una reserva, elimina el segon objecte i la coma que els separa.

### El fitxer complet

Adaptació de l'exemple de [Víctor Cárceler: DHCP con Kea](https://elpuig.xeill.net/Members/vcarceler/articulos/dhcp-con-kea), amb les dades de l'escenari d'exemple.

```json title="Fitxer JSON · Kea"
{
  "Dhcp4": {
    "interfaces-config": {
      "interfaces": [
        "enp2s0"
      ],
      "dhcp-socket-type": "raw"

    "lease-database": {

      "lfc-interval": 3600
    },
    "reservations-global": false,
    "reservations-out-of-pool": true,
    "valid-lifetime": 4000,
    "renew-timer": 1000,
    "rebind-timer": 2000,
    "subnet4": [
      {
        "id": 1,
        "subnet": "192.168.1.0/24",
        "match-client-id": false,
        "option-data": [
          {
            "name": "routers",
            "data": "192.168.1.1"
          },
          {
            "name": "domain-name-servers",
            "data": "1.1.1.1"
          },
          {
            "name": "domain-name",
            "data": "aula.internal"
          }
        ],
        "pools": [
          {
            "pool": "192.168.1.50 - 192.168.1.249"
          }
        ],
        "reservations": [
          {
            "hw-address": "08:00:27:5c:eb:99",
            "ip-address": "192.168.1.11"
          },
          {
            "hw-address": "08:00:27:2d:8d:a2",
```

## Comprovar que reparteix adreces

**DORA i renovació:** una línia de concessió al registre no demostra els quatre missatges. Conserva una captura DHCP del client inicialment sense concessió i identifica Discover, Offer, Request i ACK. Una renovació pot mostrar només Request/ACK. networkctl només gestiona interfícies de systemd-networkd; al Desktop comprova si s’utilitza NetworkManager abans de triar l’eina.

1. **El servei està actiu** i escolta pel port UDP 67:

   ```bash title="Terminal"
   systemctl status kea-dhcp4-server
   ss -ulnp | grep :67
   ```

2. **Un client rep adreça.** Amb el registre obert al servidor, engega el client i mira què hi passa:

   ```bash title="Terminal"
   sudo journalctl -u kea-dhcp4-server -f
   ```

   El registre acredita la concessió i la MAC del client. Per demostrar els quatre missatges del DORA utilitza la captura DHCP indicada abans.

3. **La concessió ha quedat desada:**

   ```bash title="Terminal"
   sudo cat /var/lib/kea/kea-leases4.csv
   ```

   Una línia amb la IP donada i la MAC de qui l'ha rebuda. Si hi ha reserva, la IP ha de ser la reservada.

## Criteris professionals

<Callout kind="bones pràctiques">

- Dimensiona el rang amb marge i evita servidors DHCP no coordinats al mateix segment.
- Una reserva permet gestionar una IP estable des del servidor, sense configurar-la al client.
- Concessions curtes en xarxes de pas; més llargues per a equips habituals.
- **Valida sempre abans d'arrencar** amb `sudo -u _kea kea-dhcp4 -t`. Estalvia la meitat dels problemes.
- **Guarda l'original** (`kea-dhcp4.conf.original`). És la teva marxa enrere si t'hi perds.
- **Escolta només per la targeta interna.** Mai posis la targeta que va a la xarxa del centre a `interfaces`.
- **Reserves fora del _pool_**, i totes juntes en una zona d'adreces baixes.
- **Comenta la configuració** amb `//`: Kea ho admet i el teu jo del mes vinent ho agrairà.

</Callout>
