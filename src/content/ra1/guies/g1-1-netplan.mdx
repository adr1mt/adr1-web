## Què hi ha en aquesta guia

Documentació oficial: [netplan.readthedocs.io](https://netplan.readthedocs.io)

- Punt de partida: Ubuntu Server amb dues targetes, `enp1s0` i `enp2s0`.
- En aquest laboratori fem servir `networkd` a Ubuntu Server.
- Treballem per **SSH des de la màquina amfitriona fins a la VM**, per poder copiar i enganxar les ordres i la configuració.

## Netplan: on s'escriu la configuració

A Ubuntu Server la xarxa es configura amb **Netplan**. Tu escrius un fitxer **YAML** a `/etc/netplan/` i Netplan tradueix aquestes instruccions al programa que realment gestiona la xarxa, que a Ubuntu Server és **systemd-networkd**.

Quan executes `netplan apply`, genera fitxers `.network` dins de `/run/systemd/network/` i qui els llegeix és systemd-networkd. Pots veure'ls tu mateix:

```bash title="Terminal"
ls /run/systemd/network/
sudo cat /run/systemd/network/*enp2s0*
```

Això importa perquè **Netplan no ho sap fer tot**. Muntar un servidor DHCP, per exemple, no està entre les seves opcions. En aquests casos s'aparta Netplan i s'escriuen els `.network` directament — és el que faràs a l'activitat 2.

## Anàlisi del fitxer de configuració

Els fitxers es llegeixen per ordre alfabètic, per això se'ls posa un número al davant: `90-xarxa.yaml`. El nom concret és igual, però l'extensió ha de ser `.yaml`.

### La capçalera

```yaml title="network"
network:
  version: 2
  renderer: networkd
  ethernets:
```

- `renderer` diu qui gestiona la xarxa: `networkd` als servidors, `NetworkManager` als escriptoris.
- A `ethernets` hi va una entrada per targeta.

### La targeta externa

```yaml title="enp1s0"
enp1s0:              # puigcastellar1 — automàtica
  dhcp4: true
```

- `dhcp4: true`: rep l'adreça, la ruta per defecte i el DNS del DHCP del centre.

### La targeta interna

```yaml title="enp2s0"
enp2s0:              # personal1 — fixa
  dhcp4: false
  addresses:
    - 192.168.1.1/24
  nameservers:
    addresses: [9.9.9.9]
```

- `addresses`: la IP fixa amb el prefix.
- `nameservers`: el DNS que farà servir el servidor.
- No hi posem porta d'enllaç: ho expliquem just a sota.

### La porta d'enllaç va en un sol lloc

En aquesta topologia volem **una sortida preferent**: el DHCP de la targeta externa aporta la ruta per defecte. No en posem cap a personal1. Un equip pot tenir diverses rutes per defecte amb mètriques o taules diferents; això requereix un disseny explícit.

Si en algun cas l'has d'escriure a mà, la sintaxi actual és aquesta. La forma antiga `gateway4:` està obsoleta i Netplan t'avisarà:

```yaml title="Fitxer YAML · Netplan"
      routes:
        - to: default
          via: 192.168.1.254
```

## El fitxer complet

`enp1s0` per DHCP i `enp2s0` amb IP fixa. És exactament l'escenari de partida d’[A1.1](../../activitats/a1-1-posada-a-punt/). **Comprova les interfícies reals i el Netplan existent de la teva VM**: `enp1s0` i `enp2s0` són els noms habituals a IsardVDI, però poden canviar.

```yaml title="Fitxer YAML · Netplan"
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0:                        # puigcastellar1 — automàtica
      dhcp4: true

    enp2s0:                        # personal1 — fixa
      dhcp4: false
      addresses:
        - 192.168.1.1/24
      nameservers:
        addresses: [9.9.9.9]
```

Tres coses del YAML que has de vigilar: la **indentació és amb espais** (mai tabuladors), cada nivell són **2 espais** més, i els dos punts van **enganxats** a la paraula.

### Si a /etc/netplan/ ja hi ha un fitxer

El nom depèn de la instal·lació: `00-installer-config.yaml` (Ubuntu Server), `01-network-manager-all.yaml` (escriptori) o `50-cloud-init.yaml` (núvol).

Netplan els llegeix **tots** per ordre alfabètic: el que va **després** afegeix claus noves o substitueix les que ja hi eren. Les llistes, com `addresses`, no se substitueixen: s'acumulen, i la targeta acaba amb totes dues adreces.

Per això no editis el fitxer del sistema: **afegeix-ne un de propi amb un número alt**, `90-xarxa.yaml`. El teu mana i l'original queda intacte. Mira com ha quedat la barreja amb `sudo netplan get`.

## Configurar les dues targetes

<Callout kind="recordatori">

Si configures la xarxa per SSH, un error et pot tallar la connexió i deixar-te fora sense manera de tornar a entrar. Fes servir sempre `sudo netplan try`: aplica els canvis temporalment i, si en 120 segons no confirmes prement Enter, els desfà sols i et retorna la connexió.

</Callout>

1. **Mira quines targetes tens** i com es diuen:

   ```bash title="Terminal"
   ip -c link show
   ```

   A IsardVDI, la primera sol ser `enp1s0` (_puigcastellar1_) i la segona `enp2s0` (_personal1_). No ho donis per fet: comprova-ho.

2. **Crea el teu fitxer** de Netplan:

   ```bash title="Terminal"
   sudo nano /etc/netplan/90-xarxa.yaml
   ```

   Enganxa el fitxer complet. L’externa es manté per DHCP; només assignes manualment la IP interna. A [A1.2](../../activitats/a1-2-dhcp-systemd-networkd/) i [A1.3](../../activitats/a1-3-dhcp-kea/) la interna serà `10.0.0.1/8`; a [A1.4](../../activitats/a1-4-kea-escala-reserves/), una IP de `172.16.0.0/16`.

3. **Posa-hi els permisos correctes.** Si no ho fas, Netplan et renyarà cada vegada:

   ```bash title="Terminal"
   sudo chmod 600 /etc/netplan/90-xarxa.yaml
   ```

4. **Comprova la sintaxi i aplica** amb la xarxa de seguretat:

   ```bash title="Terminal"
   sudo netplan try
   ```

   Si hi ha un error de sintaxi, t'ho dirà i no aplicarà res. Si tot va bé, prem Enter per confirmar.

## Comprovar que la xarxa ha quedat com volies

1. **El fitxer diu el que et penses.**

   ```bash title="Terminal"
   sudo netplan get
   ```

   Torna la configuració ja interpretada: si t'has equivocat d'indentació, aquí veuràs una cosa diferent del que has escrit.

2. **Les targetes tenen l'adreça que toca.**

   ```bash title="Terminal"
   ip -brief a
   ```

   `enp1s0` ha de tenir una adreça del centre; `enp2s0`, la `192.168.1.1/24`.

3. **Hi ha una sola ruta per defecte**, i surt per la targeta externa:

   ```bash title="Terminal"
   ip route
   ```

4. **El DNS és el que has configurat:**

   ```bash title="Terminal"
   resolvectl status
   ```

## Criteris professionals

<Callout kind="bones pràctiques">

- **No editis el fitxer del sistema.** Afegeix-ne un de propi (`90-xarxa.yaml`) amb totes les teves targetes i revisa la barreja amb `sudo netplan get`.
- **`netplan try`, mai `netplan apply`**, quan treballis per SSH.
- **Permisos 600.** El fitxer pot contenir claus de Wi-Fi.
- **Còpia de seguretat** abans de tocar-lo: `sudo cp 90-xarxa.yaml 90-xarxa.yaml.bak`.
- **Documenta amb comentaris** (`#`) quina targeta és quina. D'aquí a tres mesos no te'n recordaràs.

</Callout>
