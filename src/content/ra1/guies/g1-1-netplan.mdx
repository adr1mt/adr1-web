## Què hi ha en aquesta guia

Documentació oficial: [Netplan](https://netplan.readthedocs.io/en/stable/).

- Punt de partida: un Ubuntu Server amb dues targetes de xarxa.
- La targeta connectada a **puigcastellar1** dona sortida a Internet; la de **personal1** connecta amb la xarxa interna de pràctiques.
- **Als exàmens configurarem les dues targetes amb IP estàtica**, amb les dades de l'enunciat.

## Netplan: on s'escriu la configuració

El directori de configuració de Netplan és **`/etc/netplan`**. Dins hi trobaràs el fitxer de configuració que ha deixat la instal·lació d'Ubuntu. El nom i el contingut poden variar segons si és una versió de servidor o d'escriptori.

La configuració inicial acostuma a obtenir la IP automàticament per DHCP. Pots trobar-hi `dhcp4: true`, però no sempre apareix escrit: a l'escriptori també ho pot gestionar NetworkManager. Per configurar una IP estàtica escriurem `dhcp4: false` i les dades de xarxa.

**Editarem el fitxer que ja hi ha i hi configurarem les dues targetes.** No cal crear-ne un altre. En aquest laboratori fem servir Ubuntu Server amb `renderer: networkd`; a Ubuntu Desktop habitualment es fa servir `renderer: NetworkManager`.

## 1. Editar el fitxer existent

1. **Identifica les targetes** i els seus noms:

   ```bash title="Terminal"
   ip -brief a
   ```

   Poden dir-se `enp1s0` i `enp2s0`, però comprova quina està connectada a puigcastellar1 i quina a personal1. No donis per fet l'ordre.

2. **Entra al directori i mira què hi ha:**

   ```bash title="Terminal"
   cd /etc/netplan
   ls
   ```

   Recorda: `cd` serveix per entrar en un directori i `ls` per llistar-ne el contingut. Si hi ha més d'un fitxer `.yaml`, localitza el que configura les targetes de la pràctica; no les defineixis en diversos fitxers.

3. **Fes una còpia i obre el fitxer amb nano:**

   ```bash title="Terminal · substitueix NOM_DEL_FITXER.yaml pel nom que has vist amb ls"
   sudo cp NOM_DEL_FITXER.yaml NOM_DEL_FITXER.yaml.bak
   sudo nano NOM_DEL_FITXER.yaml
   ```

   **`NOM_DEL_FITXER.yaml` és un marcador:** escriu el nom real que t'ha mostrat `ls`. `nano` serveix per editar fitxers i `sudo` dona els permisos d'administració necessaris per modificar aquesta configuració.

4. **Configura les dues targetes en aquest mateix fitxer.** Canvia `dhcp4: true` per `dhcp4: false` si hi apareix i afegeix les adreces estàtiques. Afegeix també la segona targeta sota `ethernets`, al mateix nivell que la primera. Hi ha d'haver una sola capçalera `network:`.

   A puigcastellar1, fes servir **la IP assignada pel professorat**, el seu prefix, la porta d'enllaç i els DNS. A personal1, posa la IP i el prefix de l'enunciat, sense porta d'enllaç.

5. **Desa i surt de nano:** `Ctrl+O`, `Enter` i `Ctrl+X`.

La indentació del YAML es fa amb **espais, mai tabuladors**. En l'exemple cada nivell afegeix **2 espais**. Mantén els dos punts enganxats a la clau.

## Exemple de configuració

<details class="fold">
<summary>Mostra un exemple complet per adaptar</summary>

**És un exemple, no una solució d'examen per copiar sense canvis.** Escriu aquesta estructura en el fitxer que has obert, substituint els marcadors:

- `nom_targeta1` i `nom_targeta2`: els noms reals de les teves interfícies.
- `IP1/MÀSCARA`: la IP assignada a la targeta externa i el prefix numèric, per exemple `/22`. No hi escriguis literalment `IP1/MÀSCARA` ni una màscara amb punts.
- `10.10.10.2/8`: un exemple d'IP interna; substitueix tant la IP com el prefix pels de l'enunciat.
- La porta d'enllaç i els DNS són els de puigcastellar1 en aquest exemple; adapta'ls si l'enunciat indica altres dades.

```yaml title="Exemple · adapta'l dins del fitxer existent"
network:
  version: 2
  renderer: networkd
  ethernets:
    nom_targeta1:                  # puigcastellar1
      dhcp4: false
      addresses:
        - IP1/MÀSCARA
      nameservers:
        addresses: [192.168.236.1, 1.1.1.1]
      routes:
        - to: default
          via: 192.168.236.1

    nom_targeta2:                  # personal1
      dhcp4: false
      addresses:
        - 10.10.10.2/8
```

`renderer: networkd` correspon al servidor d'aquest laboratori. Si treballes amb Ubuntu Desktop, conserva el gestor que hi correspongui, habitualment `NetworkManager`.

</details>

## Què significa cada part

| Clau | Per a què serveix |
| --- | --- |
| `network` i `version: 2` | Inicien la configuració de Netplan. |
| `renderer` | Indica el gestor de xarxa: `networkd` en aquest servidor. |
| `ethernets` | Conté una entrada per cada targeta Ethernet. |
| `dhcp4: false` | Desactiva la configuració automàtica IPv4 per DHCP. |
| `addresses` | Defineix la IP estàtica i el prefix de la targeta. |
| `nameservers` | Defineix els DNS que farà servir l'equip. No instal·la un servidor DNS. |
| `routes` | Defineix les rutes; `to: default` amb `via` indica la porta d'enllaç. |

En aquest escenari, **la porta d'enllaç va només a la targeta de puigcastellar1**. A personal1 no hi ha cap router: els equips de la mateixa xarxa es comuniquen directament. Per això la targeta interna no porta `routes` ni necessita repetir els DNS.

## 2. Aplicar els canvis

Executa:

```bash title="Terminal"
sudo netplan apply
```

Si mostra un error, revisa el missatge, corregeix el fitxer amb nano, desa'l i torna a executar l'ordre.

<Callout kind="recordatori">

Tingues oberta la consola de la VM a IsardVDI quan canviïs la xarxa. Si treballes per SSH i canvies la IP o comets un error, la connexió es pot tallar. Des de la consola podràs corregir el fitxer; si has canviat la IP, torna a connectar-te a la nova adreça.

</Callout>

## 3. Comprovar el resultat

1. **Les dues targetes tenen les IP i els prefixos de l'enunciat:**

   ```bash title="Terminal"
   ip -brief a
   ```

2. **Hi ha una sola ruta per defecte i surt per puigcastellar1:**

   ```bash title="Terminal"
   ip route
   ```

   A l'exemple, ha d'aparèixer `default via 192.168.236.1` per la targeta externa. Si has fet servir `10.10.10.2/8` a la interna, també hi haurà una ruta directa a `10.0.0.0/8`, sense `via`.

3. **Els DNS són els que has configurat:**

   ```bash title="Terminal"
   resolvectl status
   ```

## Errors habituals

- **Error de sintaxi:** revisa els espais, els dos punts i l'alineació. Les dues targetes van al mateix nivell sota `ethernets`.
- **No apareix la IP esperada:** comprova el nom real de la targeta, `dhcp4: false` i que hagis substituït els marcadors de l'exemple.
- **Avís de permisos massa oberts:** executa `sudo chmod 600 NOM_DEL_FITXER.yaml`, amb el nom real del fitxer, i torna a aplicar.
