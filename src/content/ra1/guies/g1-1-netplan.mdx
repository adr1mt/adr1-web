## Què hi ha en aquesta guia

Documentació oficial: [netplan.readthedocs.io](https://netplan.readthedocs.io)

- Punt de partida: Ubuntu Server amb dues targetes, `enp1s0` i `enp2s0`.
- En aquest laboratori fem servir `networkd` a Ubuntu Server.
- Treballem per **SSH des de la màquina amfitriona fins a la VM**, per poder copiar i enganxar les ordres i la configuració.

## Netplan: on s'escriu la configuració

A Ubuntu Server la xarxa es configura amb **Netplan**. Tu escrius un fitxer **YAML** a `/etc/netplan/` i Netplan tradueix aquestes instruccions al programa que realment gestiona la xarxa, que a Ubuntu Server és **systemd-networkd**.

Quan executes `netplan apply`, genera fitxers `.network` dins de `/run/systemd/network/` i qui els llegeix és systemd-networkd.

## L'escenari d'exemple

Tota la guia parteix d'aquest cas. **Als exàmens configurarem sempre les dues targetes manualment, amb IP estàtica.** Les adreces d'aquí són d'exemple: a cada activitat o examen has de fer servir les dades de l'enunciat. A puigcastellar1, utilitza només la IP que t'hagin assignat per no repetir la d'un altre equip.

Tinc un Ubuntu Server a IsardVDI amb dues targetes:

- `enp1s0`, connectada a **puigcastellar1**, amb IP fixa, porta d'enllaç i DNS escrits a mà: és la sortida a Internet.
- `enp2s0`, connectada a **personal1**, amb IP fixa i sense porta d'enllaç. És una petita xarxa virtual de prova que hem creat: de moment només hi ha el nostre servidor; més endavant hi connectarem els clients als quals donarem servei amb [G1.2](../../guies/g1-2-kea/). **En aquesta xarxa no hi ha cap router.**

| Dada | Valor |
| --- | --- |
| IP fixa de `enp1s0` · puigcastellar1 | `192.168.236.60/22` |
| Porta d'enllaç · puigcastellar1 | `192.168.236.1` |
| DNS del servidor · per puigcastellar1 | `192.168.236.1` i `1.1.1.1` |
| IP fixa de `enp2s0` · personal1 | `10.10.10.2/24` |
| Porta d'enllaç · personal1 | Cap: no hi ha router |
| Fitxer | `/etc/netplan/90-xarxa.yaml` |

**No editem el fitxer que ja hi ha a `/etc/netplan/`.** En creem un de propi, `90-xarxa.yaml`, amb **les dues targetes**. Els motius són a l'apartat 2.

## 1. Configurar les dues targetes

<summary>Mostra els passos</summary>

<Callout kind="recordatori">

Si configures la xarxa per SSH, un error et pot tallar la connexió i deixar-te fora sense manera de tornar a entrar. Fes servir sempre `sudo netplan try`: aplica els canvis temporalment i, si en 120 segons no confirmes prement Enter, els desfà sols i et retorna la connexió.

</Callout>

1. **Mira quines targetes tens** i com es diuen:

   ```bash title="Terminal"
   ip -c link show
   ```

   A IsardVDI, els noms depenen de l'ordre en què s'han afegit les xarxes a l'escriptori. Aquí hem posat primer _puigcastellar1_ i després _personal1_, i per això surten com a `enp1s0` i `enp2s0`. Si les afegeixes en un altre ordre, els noms canvien: comprova-ho.

2. **Mira quin fitxer ja hi ha**, per saber què hi ha configurat. No el toquis:

   ```bash title="Terminal"
   ls /etc/netplan/
   ```

3. **Crea el teu fitxer** de Netplan:

   ```bash title="Terminal"
   sudo nano /etc/netplan/90-xarxa.yaml
   ```

   Enganxa el fitxer complet de sota, amb les dades del teu cas: **les dues targetes amb IP estàtica** i la porta d'enllaç només a l'externa.

4. **Posa-hi els permisos correctes.** Si no ho fas, Netplan et renyarà cada vegada:

   ```bash title="Terminal"
   sudo chmod 600 /etc/netplan/90-xarxa.yaml
   ```

5. **Comprova la sintaxi i aplica** amb la xarxa de seguretat:

   ```bash title="Terminal"
   sudo netplan try
   ```

   Si hi ha un error de sintaxi, t'ho dirà i no aplicarà res. Si tot va bé, prem Enter per confirmar.

</details>

## El fitxer complet · model per als exàmens

**Comprova les interfícies reals de la teva VM**: `enp1s0` i `enp2s0` són els noms habituals a IsardVDI, però poden canviar.

```yaml title="/etc/netplan/90-xarxa.yaml"
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0:                        # puigcastellar1
      dhcp4: false
      addresses:
        - 192.168.236.60/22
      nameservers:
        addresses: [192.168.236.1, 1.1.1.1]
      routes:
        - to: default
          via: 192.168.236.1

    enp2s0:                        # personal1
      dhcp4: false
      addresses:
        - 10.10.10.2/24
```

Tres coses del YAML que has de vigilar: la **indentació és amb espais** (mai tabuladors), cada nivell són **2 espais** més, i els dos punts van **enganxats** a la paraula.

## 2. Anàlisi del fitxer de configuració

<details class="fold">
<summary>Mostra l'anàlisi</summary>

Els valors són els de l'escenari d'exemple.

### El nom del fitxer

Netplan llegeix **tots** els fitxers de `/etc/netplan/` per ordre alfabètic, per això se'ls posa un número al davant. El que ja hi ha depèn de la instal·lació: `00-installer-config.yaml` (Ubuntu Server), `01-network-manager-all.yaml` (escriptori) o `50-cloud-init.yaml` (núvol).

El que va **després** afegeix claus noves o substitueix les que ja hi eren. Per això el nostre és `90-xarxa.yaml`: es llegeix l'últim i mana, i l'original queda intacte. L'extensió ha de ser `.yaml`.

Compte: les llistes, com `addresses` i `routes`, no se substitueixen, s'acumulen. Si el fitxer del sistema ja dona una IP estàtica o una ruta a una targeta, també hi continuarà sent. `dhcp4: false` desactiva el DHCP anterior, però no esborra aquestes llistes. Mira com ha quedat la barreja amb `sudo netplan get` abans d'aplicar-la; si hi ha adreces o rutes antigues, cal resoldre el conflicte amb el professorat.

### La capçalera

```yaml title="network"
network:
  version: 2
  renderer: networkd
  ethernets:
```

- `renderer` diu qui gestiona la xarxa: `networkd` als servidors, `NetworkManager` als escriptoris.
- A `ethernets` hi va una entrada per targeta.

### La targeta externa

```yaml title="enp1s0"
enp1s0:              # puigcastellar1
  dhcp4: false
  addresses:
    - 192.168.236.60/22
  nameservers:
    addresses: [192.168.236.1, 1.1.1.1]
  routes:
    - to: default
      via: 192.168.236.1
```

- `dhcp4: false`: no demana la configuració IPv4 per DHCP; l'escrivim a mà.
- `addresses`: la IP fixa `192.168.236.60` amb prefix `/22` (màscara `255.255.252.0`).
- `nameservers`: els DNS que farà servir el servidor per resoldre noms. Escriure'ls aquí no instal·la cap servei DNS.
- `routes`: la ruta per defecte envia el trànsit cap a altres xarxes al router `192.168.236.1`.
- No hi afegim `search: [mydomain, otherdomain]`: són dominis d'exemple. Només cal `search` si l'activitat indica un domini de cerca real.

### La targeta interna

```yaml title="enp2s0"
enp2s0:              # personal1
  dhcp4: false
  addresses:
    - 10.10.10.2/24
```

- `dhcp4: false`: també configurem aquesta targeta manualment.
- `addresses`: la IP del servidor a la xarxa interna, `10.10.10.2/24`.
- No hi posem `routes`: a personal1 no hi ha cap router que pugui fer de porta d'enllaç.
- Tampoc hi posem `nameservers`: de moment no hi ha cap servidor DNS en aquesta xarxa. No inventem un DNS `10.10.10.1`; el servidor ja té els DNS configurats a la targeta externa.

### La porta d'enllaç va en un sol lloc

La porta d'enllaç és un router que permet arribar a altres xarxes. A **puigcastellar1** és `192.168.236.1`, i per això hi escrivim l'única ruta per defecte d'aquest exemple.

A **personal1** només hi ha el servidor i, més endavant, els clients. Com que **no hi ha router**, no hi posem porta d'enllaç. Els equips de `10.10.10.0/24` es podran comunicar directament entre ells, sense passar per cap router. Tenir dues targetes no converteix automàticament el servidor en router: això ho configurarem a [G1.3](../../guies/g1-3-nftables/).

Fem servir `routes` amb `to: default` i `via`, com al fitxer complet. La forma antiga `gateway4:` està obsoleta i Netplan t'avisarà.

</details>

## Comprovar que la xarxa ha quedat com volies

1. **El fitxer diu el que et penses.**

   ```bash title="Terminal"
   sudo netplan get
   ```

   Torna la configuració ja interpretada: si t'has equivocat d'indentació, aquí veuràs una cosa diferent del que has escrit.

2. **Les targetes tenen l'adreça que toca.**

   ```bash title="Terminal"
   ip -brief a
   ```

   En aquest exemple, `enp1s0` ha de tenir `192.168.236.60/22`; `enp2s0`, `10.10.10.2/24`.

3. **Hi ha una sola ruta per defecte**, i surt per la targeta externa:

   ```bash title="Terminal"
   ip route
   ```

   Hi has de veure `default via 192.168.236.1 dev enp1s0` i una ruta directa a `10.10.10.0/24` per `enp2s0`. Aquesta última no porta `via`: és una xarxa connectada directament, sense porta d'enllaç.

4. **El DNS és el que has configurat:**

   ```bash title="Terminal"
   resolvectl status
   ```

## Criteris professionals

<Callout kind="bones pràctiques">

- **No editis el fitxer del sistema.** Afegeix-ne un de propi (`90-xarxa.yaml`) amb totes les teves targetes i revisa la barreja amb `sudo netplan get`.
- **`netplan try`, mai `netplan apply`**, quan treballis per SSH.
- **Permisos 600.** El fitxer pot contenir claus de Wi-Fi.
- **Còpia de seguretat** abans de tocar-lo: `sudo cp 90-xarxa.yaml 90-xarxa.yaml.bak`.
- **Documenta amb comentaris** (`#`) quina targeta és quina. D'aquí a tres mesos no te'n recordaràs.

</Callout>
